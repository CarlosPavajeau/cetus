# Security review — 2026-10-26

Review window: October 22–26, 2026, with earlier disclosures retained when relevant.
Scope: repository definitions, resolved dependencies, local tests and locally built
production images. This is a targeted review of the sources below, not an exhaustive
catalogue of worldwide incidents or a penetration test. Live Railway/AWS settings,
production certificates, account compromise, credential rotation and deployment were
not inspected or changed. Unrelated untracked planning documents were preserved.

Parent metadata was checked before overrides. The latest exporter (6.4.2) still
pins yaml 1.10.2 and js-yaml 4.3.0; latest postman-collection (5.3.1, already
resolved) still pins Faker 5.5.3 and UUID 8.3.2. Compatible transitive resolution
did not move the affected lockfile entries under the release-age policy. Scoped
overrides avoid unrelated parent updates; exact security patch exceptions in
`pnpm-workspace.yaml` preserve the general seven-day minimum.

Faker 10.5.0 is not a compatible replacement: postman-collection loads
`@faker-js/faker/locale/en` and legacy `address`, `name`, `random` and phone APIs.
The disclosed exploit targets `helpers.fake`/`rawDefinitions`, which are not the
5.5.3 implementation. Source inspection found no `faker.fake` call in
postman-collection; it binds individual generators instead. Cetus's exporter
reads only the committed spec and requests example values. No request-time
Faker path was identified. The static docs output does not serve the dependency.
The package remains vulnerable by the advisory's version range; this review does
not claim to have proved all legacy Faker expressions safe. Keep generation
limited to reviewed repository input and replace/update the exporter when an
upstream compatible fix becomes available. Do not add an audit suppression or
force the incompatible Faker major merely to obtain a clean scanner result.

Both API and worker resolve PostgreSQL JDBC **42.7.14**, centrally forced by the
Java convention plugin over Quarkus's 42.7.13. The [October 7 release](https://jdbc.postgresql.org/changelogs/2026-10-07-42.7.14-release/)
fixes requireAuth exclusions being ignored (42.7.11–13) and prior-message bytes
being written when supplied stream lengths are wrong (42.7.4–13). No custom
requireAuth exclusion or ByteStreamWriter path was found; the fixed driver is
still required to eliminate these dependency risks.

## Incident and trust review

- [Node's October security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
  supplies the retained 24.22.1 baseline in mise and both console image stages.
  It covers native DNS, TLS, decompression and bundled dependency fixes. The
  separately installed Undici package is updated independently.
- The [October 23 PHP update](https://www.cyber.gc.ca/en/alerts-advisories/al26-026-critical-vulnerabilities-impacting-php-cve-2026-109618-cve-2026-109619)
  describes CVE-2026-115560 following CVE-2026-109618/109619. It needs runtime
  serialization-handler changes and session upload progress behavior; October 21
  patches do not fix it. The authority reported public PoCs for the earlier
  issues, without identified active exploitation at that update. No PHP runtime,
  package manifest or application component was identified here.
- The [LiteLLM investigation, October 23](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain)
  attributes compromised 1.107.0 artifacts to unreclaimed exposed credentials
  and overly privileged GitHub identities. No LiteLLM dependency or image was
  identified. Repository actions already use immutable commit SHAs and read-only
  contents permissions. Railway's token is now limited to its three deployment
  jobs instead of every workflow job. Organization tokens, branch protections
  and actual secret history were outside this local review.
- [Google's eMudhra notice](https://blog.google/security/protecting-chrome-and-android-users-from-compromised-emudhra-intermediate-ca-certificates/)
  describes compromised intermediate keys and removal of emSign ECC Root CA – G3.
  Browser protections do not establish Java or OS protection. The refreshed
  Temurin base still had the root and ca-certificates 20260601~26.04.1.
  Following [Canonical's October 22 update](https://ubuntu.com/blog/emudhra-ca-compromise-fixes-available)
  and [Oracle's Java alert](https://www.oracle.com/security-alerts/alert-cve-2026-91403.html),
  image build/runtime stages update OS CA packages and remove the affected Java
  root (and AAA cross-signing anchor when present), using the shared trust script.
  Final Java images contain ca-certificates 20260816ubuntu0.26.04.1 and no G3
  or AAA anchor. Node 24.22.1's bundled roots likewise contain neither anchor.
  Other eMudhra roots remain; this is not blanket removal of that CA's roots.

The local mise-managed Java trust store also retains G3. It was inspected but not
modified outside the repository. Local developers need their own vendor trust
update; production image remediation does not modify host installations. Trust
removal can break connections to legitimate services using the removed hierarchy;
real DIAN/AWS/database/email TLS chains were not exercised.

## Application and infrastructure boundaries

| Area | Review evidence and result |
| --- | --- |
| Edge / CSRF | Production public console requests now fail closed for absent, empty or short edge secrets. Development bypass and private/health hosts remain. Seven edge tests pass. Start explicitly retains its server-function CSRF middleware; Better Auth owns its own auth endpoints. Host exceptions rely on Railway routing as documented in `edge.ts`. |
| Tenants and credentials | `ConsoleContext` derives accounts from signed organization claims; resources scope ownership. API keys are looked up by hash and active state, with suspended-account rejection. JWT verification pins issuer, audience and RS256. API suites exercise foreign-account denial, invalid credentials and roles. Signed JWTs have a five-minute lifetime; this is not instantaneous revocation of already minted JWTs. |
| Staff impersonation | Staff JWT groups require 2FA; admin endpoints have platform role checks. Better Auth and Java filters restrict impersonated credential/account mutations. Existing impersonation and organization role suites pass. |
| Webhook SSRF | Registration rejects private literals/names; worker DNS checks every returned address during the actual connection. Redirects and proxies are disabled. Existing WebhookTargets and WebhookClients tests pass. No network policy or live DNS environment was inspected. |
| Input / XML | Certificate requests limit base64 input to 200,000 characters and password length to 256; Bean Validation precedes decoding. XML helpers disable DOCTYPE/external entity paths and use secure processing. Signing and SOAP parser suites pass. No parser bypass was demonstrated. |
| Secrets / telemetry | KMS envelope encryption, S3 certificate storage, hashed API keys and one-time upload tokens are present. Telemetry configuration and console Sentry scrubbing were reviewed; IDs are kept out of metric labels. No production telemetry samples or secret values were inspected. |
| IAM / CI | Checked-in IAM policies restrict bucket prefixes, KMS key resources and sandbox deletion; no broad admin policy was found in these definitions. Actual attached policies are unverified. Actions are SHA-pinned, PR jobs have read-only contents access, install scripts are allowlisted, and deployment token scope is narrowed. |
| Containers | API/worker run as UID:GID 10001:10001 after AOT generation. Console runs as node (UID 1000), with owned app files and an owned cached pnpm installation; temporary writes remain available in /tmp. |

## Verification and remaining limits

- Java: `QUARKUS_HTTP_TEST_PORT=0 mise exec -- ./gradlew :apps:api:test
  :apps:worker:test :modules:webhooks:test :modules:signing:test
  :modules:dian-client:test` passed: 364 tests, zero failures/skips.
  A subsequent API-key run passed all four tests, including the added test that
  authenticates a key, revokes it and confirms the same credential receives 401.
  API Spotless checks passed.
- Gradle dependencyInsight confirmed 42.7.14 separately for API and worker.
- Console `check` passed (72 existing warnings, zero errors); seven edge unit
  tests passed. Docs `check`, Postman collection generation (21 requests) and
  full static build/prerender passed. Browser e2e and the full console integration
  suite were not run.
- All three production Dockerfiles built locally. Unprivileged Java AOT
  initialization and final trust-store inspection passed. Console pnpm works
  with networking disabled. API/worker readiness returned 200 with database
  checks UP against local infrastructure; console auth migrations succeeded as
  UID 1000. Console HTTP checks with explicit Host headers returned 403 for the
  public domain without an edge secret, and 200 for localhost and Railway's
  health host. Temporary smoke containers were stopped after verification.
- Docker Scout scanning was attempted but requires Docker authentication, which
  is unavailable in this session. A complete Java/OS CVE inventory was therefore
  not established; dependency/version and trust checks do not substitute for it.
- Docker flags the existing `SENTRY_AUTH_TOKEN` build ARG. No token was supplied
  to these local builds. Move live source-map credentials to a supported build
  secret mechanism after checking Railway's build integration; runtime image
  stages do not declare this ARG. Live build cache/history exposure is unverified.
- Public API behavior and schemas did not change, so public OpenAPI and console
  generated types were not regenerated. No existing migrations were edited.

Scanner success would not prove complete security. The remaining Faker match,
unavailable image CVE inventory, host Java trust update and untested live TLS
chains remain explicit limitations; this change is not a production deployment.
